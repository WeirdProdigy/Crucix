# v2.10.1 — CI-javítás: a riasztó határidő-időzítője Node 22 alatt / CI fix: the notifier deadline timer on Node 22

## Magyar

### A határidő-időzítő Node 22 alatt

- **A hiba:** a v2.10.0 CI-ja a `quality (ubuntu-24.04, 22)` mátrixágon (Node 22, Ubuntu) megbukott. A `test/alerts-notify.test.mjs` „a hanging alerter is given up on at its deadline and the other channels still report” tesztje `cancelledByParent` hibával állt le („Promise resolution is still pending but the event loop has already resolved”), és a fájl minden további tesztjét megszakította. A Node 24-es ubuntu ág sikeres volt; a Windows ágakat a fail-fast megszakította, ezért a Docker build-and-push lépés sem futott le: a 2.10.0-hoz nem készült GHCR-kép.
- **Az ok:** az értesítő (`AlertNotifier`) küldésenkénti határidő-időzítője `unref`-elt volt. Ha a próba-riasztó soha nem válaszol, és semmi más nem tartja életben az eseményhurkot, a hurok kiürül, és a Node 22 a függő ígéretet eldobja, még mielőtt a határidő lejárna. Az éles szervert ez nem érintette: ott más kezelők (például a HTTP-figyelő) életben tartják a hurkot. A hibát ugyanígy reprodukálta a helyi Windows alatti Node 22.23.3 is (a fájl 48 tesztjéből 33 sikeres, 15 megszakított).
- **A javítás:** az időzítő mostantól nem `unref`-elt, vagyis a függő küldés ideje alatt életben tartja a hurkot. A `finally` ágban törlődik, amint a riasztó válaszol vagy hibázik, és a határidőnél (legfeljebb 300000 ms) tovább nem él, így nem szivároghat, és a folyamatot sem tartja vissza a határidőn túl. A viselkedés egyébként változatlan: a határidőn túl hallgató csatorna `TimeoutError`-ral feladva marad, a többi csatorna jelentése nem késik.
- **Regressziós teszt:** a `test/fixtures/hung-alerter.mjs` gyermekfolyamatban egy soha nem válaszoló Telegram-küldést futtat 50 ms-os határidővel, úgy, hogy semmi más nem tartja életben a hurkot. A teszt azt várja, hogy a küldést a határidőnél feladja, a másik (Discord) csatorna jelentsen, a naplóban `telegram failed: TimeoutError` szerepeljen, és a folyamat 0-val lépjen ki. Ha az `unref` visszakerül, a teszt elbukik (a gyermekfolyamat 13-mal lép ki); ezt Node 22-n és Node 24-en is ellenőriztem. A tesztfutón belüli meglévő teszt Node 24-en ezt nem veszi észre, ezért kell a külön folyamat.

**Ellenőrzés:** 750 tesztből 749 sikeres, 0 hibás, 1 explicit opcionális skip (a v2.10.0 749 tesztjéhez képest **1 új**, a gyermekfolyamatos regressziós teszt), helyi Node 24.13.0 alatt (`npm test`). Ugyanez a teljes csomag Node 22.23.3 alatt is (`npx --yes node@22 --test test/*.test.mjs`): 750 teszt, 749 sikeres, 0 hibás, 0 megszakított, 1 skip; a javítás előtt ugyanezen a gépen Node 22 alatt a `test/alerts-notify.test.mjs` 33 sikeres és 15 megszakított eredményt adott. `npm run check` (177 program) rendben; `npm audit --omit=dev`: 0 ismert sérülékenység.

**GitHub CI:** a kiadási futások eredménye a kiadás után kerül ide.

**Átállás:** nincs teendő, konfiguráció vagy adat nem változott; `npm ci --ignore-scripts`, majd a szokásos indítás. A v2.10.0-hoz nincs közzétett konténerkép (a CI megbukott), ezért Docker használatakor a 2.10.1-et használd. A 2.10.0 minden egyéb része változatlan. A PWA shell gyorsítótára változatlanul `crucix-shell-v2.10.0`, mert statikus fájl nem változott.

## English

### The deadline timer on Node 22

- **The defect:** the CI of v2.10.0 failed on the `quality (ubuntu-24.04, 22)` matrix leg (Node 22 on Ubuntu). The test "a hanging alerter is given up on at its deadline and the other channels still report" in `test/alerts-notify.test.mjs` stopped with `cancelledByParent` ("Promise resolution is still pending but the event loop has already resolved") and cancelled every later test in that file. The Node 24 Ubuntu leg passed; the Windows legs were cancelled by fail-fast, so the Docker build-and-push step did not run either: there is no GHCR image for 2.10.0.
- **The cause:** the per-send deadline timer of the notifier (`AlertNotifier`) was `unref`'d. When the fake alerter never answers and nothing else keeps the event loop alive, the loop drains and Node 22 drops the pending promise before the deadline fires. The production server was not affected: there other handles (for example the HTTP listener) keep the loop alive. The same failure reproduced on Node 22.23.3 on the local Windows machine (33 of the file's 48 tests passed, 15 were cancelled).
- **The fix:** the timer is no longer `unref`'d, so it keeps the loop alive while a send is pending. It is cleared in `finally` as soon as the alerter answers or fails, and it never outlives the deadline (at most 300000 ms), so it cannot leak or hold the process beyond it. Behaviour is otherwise unchanged: a channel that stays silent past its deadline is still given up on with a `TimeoutError`, and the other channels' reports are not delayed.
- **Regression test:** the child process `test/fixtures/hung-alerter.mjs` runs a never-answering Telegram send with a 50 ms deadline in a process where nothing else keeps the loop alive. The test expects the send to be given up on at its deadline, the other (Discord) channel to report, `telegram failed: TimeoutError` in the log, and the process to exit 0. If the `unref` is put back the test fails (the child exits 13); I verified this on both Node 22 and Node 24. The existing in-runner test does not notice it on Node 24, which is why a separate process is needed.

**Validation:** 749 of 750 tests passed, 0 failed, 1 explicit optional skip (**1 new** versus the 749 tests of v2.10.0, the child-process regression test), on the local Node 24.13.0 (`npm test`). The whole suite on Node 22.23.3 as well (`npx --yes node@22 --test test/*.test.mjs`): 750 tests, 749 passed, 0 failed, 0 cancelled, 1 skipped; before the fix, on the same machine under Node 22, `test/alerts-notify.test.mjs` gave 33 passed and 15 cancelled. `npm run check` (177 programs) passes; `npm audit --omit=dev` reports 0 known vulnerabilities.

**GitHub CI:** the result of the release runs is recorded here after publication.

**Upgrade:** nothing to do, no configuration or data changed; `npm ci --ignore-scripts`, then start normally. There is no published container image for v2.10.0 (its CI failed), so use 2.10.1 when running Docker. Everything else in 2.10.0 is unchanged. The PWA shell cache stays at `crucix-shell-v2.10.0` because no static asset changed.
