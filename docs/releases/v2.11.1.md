# v2.11.1 — CI-javítás: időzítésfüggő riasztószabály-teszt Windowson / CI fix: a timing-dependent alert-rules test on Windows

## Magyar

### Az időzítésfüggő teszt

- **A hiba:** a v2.11.0 tag-futásának `quality (windows-2025, 24)` ága megbukott, az újraindítás után is. A `test/alert-rules-client.test.mjs` „Reset to default removes an override and reads the rules again; editing a built-in sends a complete override” tesztje a szabály visszaállítása után pontosan két kérést várt (`DELETE /api/alerts/rules/events-high`, majd `GET /api/alerts/rules`), a Windows/Node 24 futón azonban a kettő közé egy harmadik, `GET /api/alerts?state=all&limit=200` is bekerült. Ez a riasztó-fiók listájának újraolvasása, szándékos viselkedés; a teszt viszont a kérések teljes sorrendjét rögzítette, ezért az időzítésen múlt, hogy átmegy-e. Az ugyanilyen kódú branch-futáson átment, a tag-futáson kétszer megbukott.
- **A javítás:** a teszt csak a szabály-kéréseket (`/api/alerts/rules…`) vizsgálja ugyanabban a sorrendben, a fiók listájának újraolvasását nem. A termék kódja nem változott, a viselkedés sem.
- **Következmény a v2.11.0-ra:** a fail-fast miatt a tag-futás Docker-publikálása nem futott le, ezért a `2.11.0` és `2.11` konténercímke nem készült el; a `latest` és az SHA-címke a branch-futásból megvan, és ugyanazt a kódot tartalmazza. A v2.11.1 tag-futása már elkészíti a `2.11.1` és `2.11` címkét.

**Ellenőrzés:** 1032 tesztből 1031 sikeres, 0 hibás, 1 explicit opcionális skip (a v2.11.0-hoz képest nincs új teszt, egy teszt állítása változott), helyi Node 24.13.0 alatt (`npm test`). Ugyanez a teljes csomag Node 22.23.3 alatt is (`npx --yes node@22 --test test/*.test.mjs`): 1032 teszt, 1031 sikeres, 0 hibás, 0 megszakított, 1 skip. `npm run check`: 199 JavaScript-program rendben. `npm audit --omit=dev`: 0 sérülékenység.

**GitHub CI:** a branch- és a tag-push is magától indította a CI-t, mindkettő sikeres, mind a négy `quality` leg (ubuntu-24.04 és windows-2025, Node 22 és 24) és a GHCR Docker-build/publikálás is: [master-futás](https://github.com/mp3pintyo/Crucix/actions/runs/37087506082) és [tag-futás](https://github.com/mp3pintyo/Crucix/actions/runs/37087505958). A CI a `check`, a `test` és az `npm audit` lépést futtatja, a böngészős QA-fázisokat nem.

**Átállás:** nincs teendő, konfiguráció vagy adat nem változott; `npm ci --ignore-scripts`, majd a szokásos indítás. A v2.11.0 minden egyéb része változatlan, Dockerben a 2.11.1-et használd. A PWA shell gyorsítótára változatlanul `crucix-shell-v2.11.0`, mert statikus fájl nem változott.

## English

### The timing-dependent test

- **The defect:** the `quality (windows-2025, 24)` leg of the v2.11.0 tag run failed, and failed again after a re-run. The test "Reset to default removes an override and reads the rules again; editing a built-in sends a complete override" in `test/alert-rules-client.test.mjs` expected exactly two requests after resetting a rule (`DELETE /api/alerts/rules/events-high`, then `GET /api/alerts/rules`), but on the Windows/Node 24 runner a third one, `GET /api/alerts?state=all&limit=200`, landed between them. That is the alert tray re-reading its list, which is intended behaviour; the test, however, pinned the complete order of requests, so whether it passed depended on timing. It passed on the branch run of the same code and failed twice on the tag run.
- **The fix:** the test now checks only the rule requests (`/api/alerts/rules…`) in the same order, and ignores the tray re-reading its list. No product code and no behaviour changed.
- **Consequence for v2.11.0:** because of fail-fast, the Docker publish of the tag run did not run, so the `2.11.0` and `2.11` container tags were not built; `latest` and the SHA tag exist from the branch run and carry the same code. The tag run of v2.11.1 builds the `2.11.1` and `2.11` tags.

**Validation:** 1031 of 1032 tests passed, 0 failed, 1 explicit optional skip (no new test versus v2.11.0, one test's assertion changed), on the local Node 24.13.0 (`npm test`). The whole suite on Node 22.23.3 as well (`npx --yes node@22 --test test/*.test.mjs`): 1032 tests, 1031 passed, 0 failed, 0 cancelled, 1 skipped. `npm run check`: 199 JavaScript programs fine. `npm audit --omit=dev`: 0 vulnerabilities.

**GitHub CI:** both the branch push and the tag push started CI on their own and both succeeded, all four `quality` legs (ubuntu-24.04 and windows-2025, Node 22 and 24) and the GHCR Docker build/publish: the [master run](https://github.com/mp3pintyo/Crucix/actions/runs/37087506082) and the [tag run](https://github.com/mp3pintyo/Crucix/actions/runs/37087505958). CI runs `check`, `test` and `npm audit`, not the browser QA phases.

**Upgrade:** nothing to do, no configuration or data changed; `npm ci --ignore-scripts`, then start normally. Everything else in v2.11.0 is unchanged; use 2.11.1 when running Docker. The PWA shell cache stays at `crucix-shell-v2.11.0` because no static asset changed.
