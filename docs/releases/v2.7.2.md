# v2.7.2 — CI javítás és karbantartás / CI fix and maintenance

## Magyar

### A push mostantól magától elindítja a CI-t

- **A hiba (mérve):** ezen a forkon a CI **soha nem indult el push hatására**. A teljes futási előzményben (2026-10-01-től) kizárólag `workflow_dispatch` futások voltak, miközben a workflow-ban a `push` és `pull_request` trigger helyesen szerepelt. A pusholt commitokhoz a GitHub egyáltalán nem hozott létre `github-actions` check suite-ot (csak harmadik felek alkalmazásai kaptak), a kézi indításhoz igen. Ezért minden korábbi kiadásnál (v2.3.0–v2.7.1) a CI-t kézzel kellett indítani a tagen.
- **Kizárt okok (ellenőrizve):** az Actions engedélyezett és minden action megengedett, a workflow `active`, nincs webhook, a push szereplője a tulajdonos, a commitüzenetek nem tartalmaztak `[skip ci]` jelölést, a workflow-fájl érvényes (a hibás fájl hibás futásként látszana). A workflow letiltása majd újra engedélyezése (`gh workflow disable/enable`) **nem** segített.
- **A javítás:** a workflow-fájl (és védőtesztje) eltávolítása, push, majd azonos tartalommal visszaadása és újabb push, vagyis a GitHub újraregisztrálta a workflow-t. A régi futások megmaradtak, a korábbi changelogok CI-linkjei érvényesek. Az újraregisztráció után a `master` push **magától elindította** a CI-t. A pontos GitHub-oldali mechanizmus nem dokumentált (a közösségi beszámolók szerint a forkon létrejött workflow-regisztráció nem kapja meg a push-eseményeket), ezért a javítás tapasztalati, nem hivatalosan igazolt.

Ez megszünteti a „Node.js 20 is deprecated" figyelmeztetést. A főverzió-ugrások kiadási jegyzeteit előre átnéztem: a törő változások (Node 24 futtatókörnyezet, elavult buildx-inputok, elavult build-push környezeti változók, a metadata-action `#`-kezelése) a mi workflow-nkat nem érintik.
- A runnerek rögzítve: `ubuntu-latest` → `ubuntu-24.04`, `windows-latest` → `windows-2025`. A GitHub 2026. október 19-től fokozatosan Ubuntu 26.04-re állítja az `ubuntu-latest` címkét (befejezés: 2026. november 19.), így a kiadási build nem változik meg észrevétlenül. ## English

### Pushes now start CI automatically

- **The defect (measured):** on this fork CI **never started from a push**. The whole run history (since 2026-10-01) contains only `workflow_dispatch` runs, although the workflow correctly lists `push` and `pull_request` triggers. For pushed commits GitHub created no `github-actions` check suite at all (only third-party apps got one), while manual dispatches did. That is why every earlier release (v2.3.0–v2.7.1) needed CI to be started by hand on the tag.
- **Ruled out (verified):** Actions is enabled and all actions are allowed, the workflow is `active`, there are no webhooks, the pusher is the owner, commit messages contained no `[skip ci]` marker, and the workflow file is valid (an invalid file would appear as a failed run). Disabling then re-enabling the workflow (`gh workflow disable/enable`) did **not** help.
- **The fix:** removing the workflow file (and its guard test), pushing, then restoring identical content and pushing again, so GitHub registered the workflow afresh. Old runs were kept, so the CI links in earlier changelogs stay valid. After re-registration the `master` push **started CI by itself**. The exact GitHub-side mechanism is undocumented (community reports say a workflow registered on a fork does not receive push events), so the fix is empirical rather than officially confirmed.

### Actions and runners

- Every action is on a **Node 24** release, pinned to a full commit SHA with an exact version comment: `actions/checkout` v7.0.1, `actions/setup-node` v7.0.0, `docker/setup-qemu-action` v4.4.0, `docker/setup-buildx-action` v4.4.1, `docker/login-action` v4.6.0, `docker/metadata-action` v6.2.0, `docker/build-push-action` v7.4.0. This clears the "Node.js 20 is deprecated" notice. The release notes of the major jumps were reviewed beforehand: the breaking changes (Node 24 runtime, removed buildx inputs, removed build-push environment variables, metadata-action `#` handling) do not affect this workflow.
- Runners are pinned: `ubuntu-latest` → `ubuntu-24.04`, `windows-latest` → `windows-2025`. GitHub moves the `ubuntu-latest` label to Ubuntu 26.04 gradually from 2026-10-19 (completion by 2026-11-19), so release builds can no longer change unnoticed. The condition of the Linux-only `npm audit` step follows the pinned label.
- A new `test/workflow.test.mjs` (4 tests) guards that every action is pinned to a full SHA with an exact version comment, that no floating `-latest` runner label returns, that the audit step targets a runner present in the matrix, and that the `master`/`v*` triggers remain.

**Validation:** 310 of 311 tests passed, 0 failed, 1 explicit optional skip (4 new versus the 307 tests of v2.7.1, the workflow guard tests); `npm run check` (144 programs) passes. The result of the push-triggered CI run is below.

**GitHub CI:** the first run started **by a push on its own** after the fix: [successful run](https://github.com/mp3pintyo/Crucix/actions/runs/36983053838) — pinned runners (ubuntu-24.04, windows-2025), Node 22/24 and GHCR Docker build/publication, **without warnings** (the "Node.js 20 is deprecated" and `ubuntu-latest` migration notices are gone; the run has no annotations). Both the branch push and the tag push of `v2.7.2` were started by GitHub on its own: [master run](https://github.com/mp3pintyo/Crucix/actions/runs/36983279519) and [tag run](https://github.com/mp3pintyo/Crucix/actions/runs/36983279675), both successful.

**Upgrade:** nothing to do. No runtime code, dependency or configuration changed. From now on a tag push starts CI by itself; a manual `workflow_dispatch` is no longer needed.
