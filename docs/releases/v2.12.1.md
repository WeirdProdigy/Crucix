# v2.12.1 — CI-javítás: sortörés-érzékeny teszt Windowson / CI fix: a line-ending-sensitive test on Windows

## Magyar

### A sortörés-érzékeny teszt

- **A hiba:** a v2.12.0 mindkét CI-futásán (branch- és tag-push) megbukott a Windows-os `quality` ág (a branch-futáson a Node 24, a tag-futáson a Node 22 változat). A hibás teszt a `test/changes-ui.test.mjs` „the English fallback text of the module is the English locale text, key for key” tesztje volt: a `dashboard/public/changes.js` forrásszövegéből egy reguláris kifejezéssel (`…\n  let opts`) olvassa ki a beépített angol szövegtáblát, és összeveti a `locales/en.json` megfelelő csoportjával. A Windows-os CI-futón a repó CRLF sortörésekkel kerül ki, ezért a kifejezés nem talált, és a teszt `the COPY table` hibával állt le. A többi három ág (Ubuntu, mindkét Node) sikeres volt, de a fail-fast miatt a Docker build-and-push lépés egyik futáson sem futott le.
- **A javítás:** a kifejezés mostantól `\r?\n`-t fogad el. A termék kódja nem változott, a viselkedés sem.
- **Ellenőrzés a hibás környezetben:** a hibát a helyi gépen azért nem láttam, mert itt a munkamásolat LF sortöréses. A javítás után a repót `core.autocrlf=true` beállítással klónoztam (a fájlokban CRLF van, mint a Windows-os CI-n), és abban futtattam a teljes tesztcsomagot: 1401 teszt, 1400 sikeres, 0 hibás, 1 skip. Ezt a lépést innentől minden kiadás előtt elvégzem.
- **Következmény a v2.12.0-ra:** a v2.12.0 funkciói és minden más része változatlan; a konténerkép viszont egyik futásból sem készült el (a `latest`, a `2.12.0` és a `2.12` címke hiányzik), ezért Dockerben a 2.12.1-et használd.

**Ellenőrzés:** 1401 tesztből 1400 sikeres, 0 hibás, 1 explicit opcionális skip (a v2.12.0-hoz képest nincs új teszt, egy teszt reguláris kifejezése változott), helyi Node 24.13.0 alatt (`npm test`). Ugyanez a teljes csomag Node 22.23.3 alatt is (`npx --yes node@22 --test test/*.test.mjs`), és CRLF sortörésű klónban is (lásd fent). `npm run check`: 228 JavaScript-program rendben. `npm audit --omit=dev`: 0 sérülékenység.

**GitHub CI:** a branch- és a tag-push is magától indította a CI-t, mindkettő sikeres, mind a négy `quality` leg (ubuntu-24.04 és windows-2025, Node 22 és 24) és a GHCR Docker-build/publikálás is: [master-futás](https://github.com/mp3pintyo/Crucix/actions/runs/37134554048) és [tag-futás](https://github.com/mp3pintyo/Crucix/actions/runs/37134554105). A CI a `check`, a `test` és az `npm audit` lépést futtatja, a böngészős QA-fázisokat nem.

**Átállás:** nincs teendő, konfiguráció vagy adat nem változott; `npm ci --ignore-scripts`, majd a szokásos indítás. A PWA shell gyorsítótára változatlanul `crucix-shell-v2.12.0`, mert statikus fájl nem változott.

## English

### The line-ending-sensitive test

- **The defect:** on both CI runs of v2.12.0 (the branch push and the tag push) the Windows `quality` leg failed (Node 24 on the branch run, Node 22 on the tag run). The failing test was "the English fallback text of the module is the English locale text, key for key" in `test/changes-ui.test.mjs`: it extracts the built-in English text table from the source text of `dashboard/public/changes.js` with a regular expression (`…\n  let opts`) and compares it with the matching group of `locales/en.json`. On the Windows CI runner the repository is checked out with CRLF line endings, so the expression found nothing and the test stopped with `the COPY table`. The other three legs (Ubuntu, both Node versions) passed, but because of fail-fast the Docker build-and-push step did not run on either run.
- **The fix:** the expression now accepts `\r?\n`. No product code and no behaviour changed.
- **Checked in the failing environment:** I did not see the failure locally because the working copy here has LF line endings. After the fix I cloned the repository with `core.autocrlf=true` (CRLF in the files, as on the Windows CI) and ran the whole test suite there: 1401 tests, 1400 passed, 0 failed, 1 skipped. From now on I do this before every release.
- **Consequence for v2.12.0:** the v2.12.0 features and everything else are unchanged; however, no container image was built by either run (the `latest`, `2.12.0` and `2.12` tags are missing), so use 2.12.1 when running Docker.

**Validation:** 1400 of 1401 tests passed, 0 failed, 1 explicit optional skip (no new test versus v2.12.0, one test's regular expression changed), on the local Node 24.13.0 (`npm test`). The whole suite on Node 22.23.3 as well (`npx --yes node@22 --test test/*.test.mjs`), and in a CRLF clone (see above). `npm run check`: 228 JavaScript programs fine. `npm audit --omit=dev`: 0 vulnerabilities.

**GitHub CI:** both the branch push and the tag push started CI on their own and both succeeded, all four `quality` legs (ubuntu-24.04 and windows-2025, Node 22 and 24) and the GHCR Docker build/publish: the [master run](https://github.com/mp3pintyo/Crucix/actions/runs/37134554048) and the [tag run](https://github.com/mp3pintyo/Crucix/actions/runs/37134554105). CI runs `check`, `test` and `npm audit`, not the browser QA phases.

**Upgrade:** nothing to do, no configuration or data changed; `npm ci --ignore-scripts`, then start normally. The PWA shell cache stays at `crucix-shell-v2.12.0` because no static asset changed.
