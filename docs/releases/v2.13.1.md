# v2.13.1 — A fork saját arca: az upstream demó- és közösségi hivatkozások eltávolítva, proxy-addr frissítve / The fork's own face: upstream demo and community links removed, proxy-addr updated

## Magyar

### A README már nem hivatkozik az upstream címekre

- **Miért:** ez a repó az eredeti `calesthio/Crucix` forkja, a `https://www.crucix.live/` demóoldal viszont nem ennek a forknak a címe. A README így olyan oldalra irányította az olvasót, amely nem ezt a kódot futtatja.
- **Eltávolítva a [README.md](../../README.md)-ből:** a „Visit The Upstream Demo: crucix.live” cím, a két `crucix.live` jelvény (Live Website, Open Demo), a „Upstream demo” megjegyzés és a „Try the live demo first…” mondat. Ugyanígy kikerült az „Enter The Signal Network” blokk is: a Signal Wire (X, `@crucixmonitor`) és az Ops Room (Discord) jelvény, mert ezek is az eredeti projekt közösségi csatornái.
- **Hozzáadva:** egy rövid „Fork” megjegyzés, amely az eredeti `calesthio/Crucix` repóra mutat, így a származás továbbra is látható.
- **Nem változott:** a termék kódja, a tesztek és a dashboard. A README többi része, a telepítési és üzemeltetési útmutató is változatlan. Az upstreamre utaló nyomok a repó követett fájljaiban sem maradtak (`git grep`: nincs találat a `crucix.live`, `crucixmonitor`, `ChVy7SF4` vagy „Signal Network” szövegre a docs/superpowers terv, a tesztek és a dashboard `crucix.*` localStorage-kulcsai nélkül, utóbbiak nem címek).

### A `proxy-addr` frissítése (CI-javítás)

- **A hiba:** az `npm audit --omit=dev` új, kritikus súlyosságú találatot jelzett az Expressen keresztül behúzott `proxy-addr` 2.0.7-re ([GHSA-jqcg-44mw-7w3h](https://github.com/advisories/GHSA-jqcg-44mw-7w3h), IP-hamisítás az IPv4-leképezett IPv6 megbízható alhálózaton át). A találat a README-változtatástól függetlenül, a tiszta fán is megvolt, és a CI `npm audit` lépése elbukott volna.
- **A javítás:** csak a `package-lock.json` változott, a `proxy-addr` 2.0.7 → 2.0.8 (az Express 5.2.1 által megengedett tartományon belül). A `package.json` függőségei nem változtak. A kód nem használ `trust proxy` beállítást, így a sebezhetőség a Crucix alapértelmezett működését nem érintette; a frissítés a tiszta audit miatt kellett.

**Ellenőrzés:** 1420 tesztből 1419 sikeres, 0 hibás, 1 explicit opcionális skip (nincs új teszt, kód nem változott), helyi Node v24.13.0 alatt (`npm test`), a `proxy-addr` frissítése után is. `npm run check`: 245 JavaScript-program és a nyelvi ellenőrzés rendben. `npm audit --omit=dev`: a frissítés előtt 1 kritikus találat, utána 0 sérülékenység. Nem futtattam újra a Node 22-es és a CRLF-es (Windowsos CI-másolat) csomagot, mert ebben a kiadásban kizárólag a README, a verziószám és egy lockfile-bejegyzés változott, kód nem; a böngészős QA-t sem, mert statikus fájl nem változott. A GitHub CI a `check`, a `test` és az `npm audit` lépést futtatja.

**Átállás:** nincs teendő, konfiguráció vagy adat nem változott; `npm ci --ignore-scripts`, majd a szokásos indítás (a lockfile a `proxy-addr` 2.0.8-at hozza). A PWA shell gyorsítótára változatlanul `crucix-shell-v2.13.0`, mert statikus fájl nem változott.

## English

### The README no longer links to upstream addresses

- **Why:** this repository is a fork of the original `calesthio/Crucix`, but the demo site `https://www.crucix.live/` is not this fork's address. The README therefore sent readers to a site that does not run this code.
- **Removed from [README.md](../../README.md):** the "Visit The Upstream Demo: crucix.live" heading, the two `crucix.live` badges (Live Website, Open Demo), the "Upstream demo" note and the "Try the live demo first…" sentence. The "Enter The Signal Network" block went as well: the Signal Wire (X, `@crucixmonitor`) and Ops Room (Discord) badges, because those are the original project's community channels.
- **Added:** a short "Fork" note pointing to the original `calesthio/Crucix` repository, so the origin stays visible.
- **Unchanged:** the product code, the tests and the dashboard. The rest of the README, including the installation and operations guide, is unchanged. No trace of the upstream addresses is left in the repository's tracked files either (`git grep`: no hit for `crucix.live`, `crucixmonitor`, `ChVy7SF4` or "Signal Network", leaving aside the docs/superpowers plan, the tests and the dashboard's `crucix.*` localStorage keys, which are not addresses).

### The `proxy-addr` update (CI fix)

- **The defect:** `npm audit --omit=dev` reported a new critical-severity finding for `proxy-addr` 2.0.7, pulled in through Express ([GHSA-jqcg-44mw-7w3h](https://github.com/advisories/GHSA-jqcg-44mw-7w3h), IP spoofing via the IPv4-mapped IPv6 trusted subnet). The finding existed on the clean tree regardless of the README change, and the CI `npm audit` step would have failed.
- **The fix:** only `package-lock.json` changed, `proxy-addr` 2.0.7 → 2.0.8 (within the range Express 5.2.1 allows). The dependencies in `package.json` did not change. The code uses no `trust proxy` setting, so Crucix's default behaviour was not exposed; the update was needed for a clean audit.

**Validation:** 1419 of 1420 tests passed, 0 failed, 1 explicit optional skip (no new test, no code changed), on the local Node v24.13.0 (`npm test`), also after the `proxy-addr` update. `npm run check`: 245 JavaScript programs and the locale check pass. `npm audit --omit=dev`: 1 critical finding before the update, 0 vulnerabilities after. I did not re-run the Node 22 suite or the CRLF (Windows CI replica) suite, because this release changes only the README, the version number and one lockfile entry, no code; nor the browser QA, because no static asset changed. GitHub CI runs `check`, `test` and `npm audit`.

**Upgrade:** nothing to do, no configuration or data changed; `npm ci --ignore-scripts`, then start normally (the lockfile brings `proxy-addr` 2.0.8). The PWA shell cache stays at `crucix-shell-v2.13.0` because no static asset changed.
