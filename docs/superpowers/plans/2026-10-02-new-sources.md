# New Live Sources Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add ten free, keyless live sources (IMF PortWatch, EMSC, Copernicus EMS, adsb.lol military aggregates, aviation SIGMETs, OpenSanctions index, Federal Register, Energy-Charts HU, ENTSOG HU, prediction markets) to the "Current public data" pipeline, removing the nine-source limit, and feed them into events, history, the map and the B alert engine.

**Architecture:** One `apis/sources/<name>.mjs` per source (pure `parseXxx(payload,{now})` + `briefing(options)`, same contract as `epss.mjs`/`gdacs.mjs`), registered in `POLICIES`, the browser-side `policies` copy, `HOME`, `FACT_FIELDS` and `apis/briefing.mjs`; framework limits and kind lists are generalised first; integration (map kind table, alert metrics, fixture/QA, docs) comes last.

**Tech Stack:** Node 22/24 ESM, `node:test`, `safeFetch` (apis/utils/fetch.mjs), `freshResult`/`unavailableResult` (apis/utils/freshness.mjs), `fast-xml-parser` via apis/utils/xml.mjs (only if a source is XML), vanilla browser JS, optional Playwright QA.

**Spec:** `docs/superpowers/specs/2026-10-02-new-sources-design.md` (authoritative table of sources, kinds, severities, freshness defaults and licences).

## Global Constraints

- Node 22/24 ESM; no new runtime dependency; no keys or accounts; adapters never throw out of `briefing()` (network/parse failure -> `unavailableResult` with a message free of secrets and full URLs); no timers left running or `unref`'d (Node 22 on Linux drops pending promises on an empty event loop - CI failed once on exactly that); every implementer runs their new test files under Node 22 as well: `npx --yes node@22 --test <files>`.
- Per source: `SOURCE` string = `POLICIES` key; `observedAt` is provider time (never collection time, never a substitute); rows pre-sorted/capped BEFORE `freshResult` (it slices the first 100 before filtering); stable `providerId` (no timestamp unless the record itself is that day/instant, e.g. `szoros:YYYY-MM-DD`); each row has its own deep link (history merges rows with the same kind + URL); only whitelisted fields; provider text cut/cleaned with the existing `text()` rules; `attribution`, `rights`, `license`, `licenseUrl` set from the provider's actual terms (verify on the provider's page, quote the real licence); request limits `{timeout: 10000, retries: 0, maxBytes: 2 MiB}`, at most 3 requests per briefing() call except where the brief says otherwise; per-adapter in-memory cache (like `epss.mjs`: bounded Map, TTL, `ok` results only) for slow-moving sources.
- Source registration checklist (every adapter task does ALL of it): (1) adapter file; (2) `apis/utils/freshness.mjs` `POLICIES` entry appended at the END (same key order is asserted against the browser copy by JSON.stringify); (3) the same entry appended in `dashboard/public/live-sources.js` `policies`; (4) `lib/intelligence/live-sources.mjs` `HOME` and `FACT_FIELDS` entries (key sets must equal POLICIES; `[]` when no facts); (5) `apis/briefing.mjs` import + `runSource(...)` call next to the existing nine (+ `crucix.config.mjs` `publicSources` list when the brief names one); (6) `locales/en.json|hu.json|fr.json`: `inspector.fact.<key>` for every new fact key (natural HU/FR; parity test enforces); (7) `test/sources-<name>.test.mjs` with inline trimmed fixtures captured from the live endpoint (verify the endpoint live with a read-only GET first; if it is unusable report that with evidence instead of guessing - the other sources do not depend on it); (8) no edits to other adapters.
- Kinds: `LIVE_KINDS` gains `earthquake`, `maritime`, `aviation`, `sanctions`, `market`, `energy` in Task 1 (rows of any other kind become `signal` and never reach events).
- Severity words must pass `normalizeSeverity` (info/monitor/low/moderate/elevated/high/critical or the provider aliases); the repo's CAP rule is Severe -> HIGH, Extreme -> CRITICAL.
- Existing tests stay green; no private data in tests; commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; implementers never push, tag or publish. Version 2.11.0 and `sw.js` cache `crucix-shell-v2.11.0` in the last task only.

## Review Focus

- A source that is down, slow, returns 403/429/5xx, malformed JSON, a changed shape or a 2 MiB+ body must degrade to that source's `error` state only, never stop the sweep or the briefing (Tasks 2-7, 8).
- Row identity must be stable across consecutive parses of the same payload and across sweeps (history must not grow every sweep); rows with the same URL must not collapse (Tasks 2-7).
- Hostile provider text (markup, control/bidi characters, huge strings) stays inert end to end; rows are capped and ranked before `freshResult`'s first-100 slice (Tasks 2-7).
- Freshness: old, future-dated, undated and `validUntil`-expired rows never appear as current; aggregates (adsb.lol theaters, PortWatch baselines) are never presented as provider observations of something they are not (Tasks 2-7).
- Framework: no remaining nine-source limit; the browser `policies` copy, `HOME`, `FACT_FIELDS`, kind lists and locale fact keys stay consistent for all 19 sources; PWA snapshot stays under 5 MiB with 19 sources at the row caps (Tasks 1, 8).
- Everything passes on Node 22, not just Node 24 (all tasks; final gate before tagging).
